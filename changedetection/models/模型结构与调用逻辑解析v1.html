0.2 四个组件的装配关系与数据流

STMambaSCD 构造时注册四个组件：

encoder      = Backbone_VSSM          # ① T1/T2 权重共享, 输出 4 级特征
decoder_bcd  = ChangeDecoder          # ② 双时相输入, 产出变化图
decoder_T1   = SemanticDecoder        # ③ 结构同、参数独立
decoder_T2   = SemanticDecoder        #    二者共用同一份 change_maps
main_clf_cd  = PyramidFusion(128→2)   # ④ BCD 分类头
aux_clf      = PyramidFusion(128→C)   #    T1/T2 共用的语义分类头

forward(pre_data, post_data) 的数据流（尺寸按 dims=[128,256,512,1024]）：

pre_data ─┐
          ├─► encoder 各跑一遍 ─► pre_features / post_features
post_data ┘                       [(B,128,H/4),(B,256,H/8),(B,512,H/16),(B,1024,H/32)]

①► ChangeDecoder(pre, post)
      每级: FFT_Fusion(JSF空频融合) → VSSBlock(Mamba时空建模)
      金字塔自上而下: p4→p3→p2→p1 (upsample_add + ResBlock平滑 + VSSBlock)
      返回 (p1, change_maps=[p4,p3,p2,p1] 粗→细)

②► change_maps[::-1] 反转成细→粗, 与 feat_1~feat_4 尺度一一对应

③► decoder_T1(pre_features, change_maps)  ┐ 每级: CGA(特征×sigmoid(变化图))
    decoder_T2(post_features, change_maps)┘      → VSSBlock → ResBlock → PyramidFusion下采样
    各返回 (B,128,H/4,W/4)

④► main_clf_cd(p1) → output_bcd  (B,2,H,W)
    aux_clf(T1/T2输出) → output_T1/output_T2 (B,C,H,W)
    三个输出统一 F.interpolate 双线性上采样回原图尺寸

衔接关键：STMambaSCD.py:149 的 change_maps[::-1] —— ChangeDecoder 按粗→细产出，SemanticDecoder 按细→粗消费。BCD 分支的产出 change_maps 是 SCD 分支的引导输入，这是两个分支之间的"暗线"。

1ChangeDecoder —— BCD 解码器逐层级解析

以下按典型配置讲解：encoder_dims=[128,256,512,1024]（由 EMBED_DIM 翻倍推出），输入影像 (B,3,H,W)，channel_first=True（默认 ln2d 配置）。

1.1 构造函数：零件清单

ChangeDecoder.__init__ 注册 4 组零件，全部按由粗到细的方向组织：

组件实例作用层级通道数
JSF 空频融合 ×4fuse_layer_1最粗级 1/321024
fuse_layer_21/16512
fuse_layer_31/8256
fuse_layer_4最细级 1/4128
VSSBlock ×4st_block_41最粗级1024
st_block_311/16512
st_block_211/8256
st_block_11最细级128
PyramidFusion ×3down_sample_1粗→细过渡1024→512
down_sample_2512→256
down_sample_3256→128
ResBlock ×3smooth_layer_3/2/11/16、1/8、1/4 级各级等宽
⚠ 命名陷阱 fuse_layer_1 配对的是 pre_feat_4（最粗级），不是 feat_1。st_block_41 的第一个下标 4 表示编码器 stage 4（最粗），第二个下标 1 无含义、纯风格命名。

每个 st_block_* 都是三层包裹：

nn.Sequential(
    Permute(0,2,3,1) if not channel_first else nn.Identity(),  # LN时才需要转置
    VSSBlock(hidden_dim=..., drop_path=0.1, ...),
    Permute(0,3,1,2) if not channel_first else nn.Identity(),
)

默认 ln2d 配置下两个 Permute 都是 Identity，直接进出 (B,C,H,W)。

1.2 forward 入口拆包

pre_feat_1, pre_feat_2, pre_feat_3, pre_feat_4 = pre_features
# feat_1: (B,128,H/4,W/4) 最细 ← feat_4: (B,1024,H/32,W/32) 最粗

1.3 Stage I —— 最粗级（1/32，1024 通道）

金字塔的"起点"，没有粗先验可加，只有两步：

p4 = self.fuse_layer_1(pre_feat_4, post_feat_4)   # ① JSF 空频融合
p4 = self.st_block_41(p4)                          # ② Mamba 时空建模
p4_attention = p4                                  # ③ 存为最粗变化图
p4 = self.down_sample_1(p4)                        # ④ 通道降维 1024→512，传给下一级

① FFT_Fusion(1024) 内部（GuidedFusion.py:316-338），5 路拼接

输入: pre (B,1024,h,w), post (B,1024,h,w)，记 h=H/32

1. pre_freq  = fft_pre(pre)    # FFTBranch: torch.fft.fft2 → log1p(|幅度谱|) → 1x1投影+BN+ReLU
2. post_freq = fft_post(post)  # 同上
3. cat = [pre, pre_freq, post, post_freq, |pre−post|]   # 1024×5 = 5120 通道
4. reduce_conv(1x1) + BN + ReLU:  5120 → 1024
5. ch_gate (ECA通道门控): GAP → 1D卷积 → sigmoid → 逐通道加权
6. sp_gate (空间门控): 通道max+avg → 7x7conv → sigmoid → 逐像素加权
输出: (B,1024,h,w)
ℹ 源码细节 forward 里先拼了一次 [pre, post]，开了 FFT 分支后又重新拼 [pre, pre_freq, post, post_freq] 覆盖掉，第一次拼接实际是无效操作。

② st_block_41 内部（VSSBlock，vmamba.py:1349）

x + DropPath(SS2D(norm(x))) + DropPath(MLP(norm2(x)))

SS2D 是 2D 选择性扫描：特征展平成序列后沿 4 个方向（交叉扫描）做 Mamba 线性复杂度的时序建模，在这里承担双时相融合特征的空间上下文建模。norm 是 LayerNorm2d（按配置）。

④ down_sample_1 = PyramidFusion(1024→512)（GuidedFusion.py:108-128）

b1 = Conv1x1(1024→512)+BN+ReLU          # 逐像素分支
b3 = Conv3x3(1024→512)+BN+ReLU          # 小感受野
b5 = DWConv5x5 → Conv1x1(→512)+BN+ReLU  # 大感受野（深度可分离）
cat[b1,b3,b5] (1536ch)
→ ChannelAttention: avg+max池化 → 共享FC → sigmoid → 通道加权
→ SpatialAttention: 7x7conv → sigmoid → 空间加权
→ final_conv 1x1: 1536→512
+ shortcut(Conv1x1 1024→512)            # 残差
输出: (B,512,h,w)
⚠ 关键认知 PyramidFusion 不改空间分辨率，"下采样"只指通道减半。分辨率从 1/32 升到 1/16 是在下一级的 _upsample_add 里完成的。

1.4 Stage II —— 1/16，512 通道（完整五步流水线）

p3 = self.fuse_layer_2(pre_feat_3, post_feat_3)   # ① JSF 融合 → (B,512,H/16,W/16)
p3 = self._upsample_add(p4, p3)                    # ② 注入粗先验
p3 = self.smooth_layer_3(p3)                       # ③ ResBlock+SE 平滑
p3 = self.st_block_31(p3)                          # ④ VSSBlock 时空建模
p3_attention = p3                                  # ⑤ 存变化图
p3 = self.down_sample_2(p3)                        # ⑥ 512→256

② _upsample_add(p4, p3)（ChangeDecoder.py:108-111）—— 金字塔融合的核心一步

_, _, H, W = y.size()                              # y = p3, (B,512,H/16,W/16)
return F.interpolate(x, size=(H, W), mode='bilinear') + y
# p4 (B,512,H/32,W/32) 双线性放大 2 倍 → 与 p3 逐元素相加

此时 p4 已经是 512 通道（上一级 down_sample_1 的产物），所以通道对齐靠 PyramidFusion，分辨率对齐靠 interpolate，两者分工明确。这一步把最粗级的全局变化语义以"加法 skip"的形式灌进本级。

③ smooth_layer_3 = ResBlock(512,512,stride=1)（ResBlockSe.py:32-52）

out = Conv3x3+BN+ReLU → Conv3x3+BN
out = SE(out)          # SE通道注意力插在残差路径上（注意是在 +identity 之前）
out += identity        # 等宽等 stride，identity 就是原始输入
out = ReLU(out)

SE 在 +identity 之前意味着恒等分支加回来的是未经 SE 的原特征——这是标准 ResNet+SE 写法的一个变体（原版 SE-Network 也是这么插的）。

1.5 Stage III —— 1/8，256 通道

与 Stage II 完全同构，只是换了实例和通道：

p2 = self.fuse_layer_3(pre_feat_2, post_feat_2)   # FFT_Fusion(256) → (B,256,H/8,W/8)
p2 = self._upsample_add(p3, p2)                    # p3 已被 down_sample_2 降到 256ch
p2 = self.smooth_layer_2(p2)                       # ResBlock(256)
p2 = self.st_block_21(p2)                          # VSSBlock(256)
p2_attention = p2
p2 = self.down_sample_3(p2)                        # 256→128

1.6 Stage IV —— 最细级（1/4，128 通道）

流程同 Stage II/III，但没有第⑥步——已到最细分辨率，不再下采样：

p1 = self.fuse_layer_4(pre_feat_1, post_feat_1)   # FFT_Fusion(128) → (B,128,H/4,W/4)
p1 = self._upsample_add(p2, p1)                    # p2 已是 128ch，放大 2 倍相加
p1 = self.smooth_layer_1(p1)                       # ResBlock(128)
p1 = self.st_block_11(p1)                          # VSSBlock(128)
p1_attention = p1
# 没有 down_sample —— 最细级到此为止
return p1, change_maps

1.7 返回值组装（ChangeDecoder.py:165-167）

change_maps = [p4_attention, p3_attention, p2_attention, p1_attention]
return p1, change_maps
  • p1：(B,128,H/4,W/4)，交给 STMambaSCD.main_clf_cd（PyramidFusion 128→2）出二元变化图；
  • change_maps：粗→细顺序的 4 张图，就是各级 VSSBlock 之后、下采样之前的那份融合特征。调用方 STMambaSCD.py:149 会做 change_maps[::-1] 反转成细→粗，再喂给 SemanticDecoder。
★ change_maps 的物理意义 p4_attention 等是双时相融合特征本身，不是显式监督出来的分割图。它们之所以能当"变化先验"用，是因为生成路径里包含 |pre−post| 差分和 FFT 频域对比——变化区域在这些算子下响应强，融合特征值高。SemanticDecoder 拿它做 sigmoid 后就变成了天然的 (0,1) 空间注意力图。注意 change_maps 通道数与各级特征天然等宽（1024/512/256/128），这正是 CGA 能直接逐元素相乘、不需要投影卷积的前提。

1.8 单级数据流总图（以 Stage II 为例）

pre_feat_3 (B,512,H/16) ──┐
                          ├─► fuse_layer_2 (JSF) ─► (B,512,H/16)
post_feat_3 (B,512,H/16) ─┘                              │
p4_prev (B,512,H/32) ─► interpolate↑2x ──────────────────┤ +  ← _upsample_add
                                                         ▼
                                              smooth_layer_3 (ResBlock+SE)
                                                         ▼
                                              st_block_31 (VSSBlock/SS2D)
                                                         ▼
                                              ┌─ p3_attention (存入 change_maps)
                                              ▼
                                     down_sample_2 (PyramidFusion 512→256)
                                                         ▼
                                          传给 Stage III 做 _upsample_add

一句话概括：每级先"双时相合成"（JSF），再"接收上级先验"（上采样相加）、"去噪精修"（ResBlock+SE）、"时空建模"（Mamba SS2D），然后把建模后的特征一分为二——一份留作该级变化先验图，一份降通道传给更细一级。四个 stage 从 1/32 一路走到 1/4，逐级把粗粒度的全局变化语义注入细粒度特征。

2encoder = Backbone_VSSM（独立解析）

定位：从 VMamba 分类骨干改造来的多尺度特征提取器，T1/T2 共用同一份权重（forward 里各跑一遍）。

2.1 构造时做了什么（Mamba_backbone.py:24-48）

继承父类 VSSM 后做三处手术：

  1. 删分类头：del self.classifier——父类末尾的 norm→avgpool→Linear(→1000) 整段扔掉，只留特征提取部分；
  2. 挂 4 个输出归一化层：给 out_indices=(0,1,2,3) 每个 stage 加一个独立模块 outnorm0~3（默认 ln2d 配置下即 LayerNorm2d(128/256/512/1024)）；
  3. 加载预训练：load_pretrained 用 strict=False 载入 VMamba 官方 ckpt（骨干层匹配的键生效，不匹配的分类头键自动忽略）。

同时记录 self.channel_first = True（ln2d 配置）并暴露 self.dims=[128,256,512,1024]——下游所有解码器的通道配置都从这里取。

2.2 stage 容器结构（父类提供）

self.layers[i] 每个都是一个 OrderedDict 包的 Sequential：

nn.Sequential(OrderedDict(
    blocks=nn.Sequential(*[VSSBlock×depths[i]]),  # 当前分辨率下的特征变换
    downsample=conv_s2+norm 或 nn.Identity,        # 传给下一 stage 的降采样
))

2.3 forward 逐级调用（Mamba_backbone.py:66-91）

本类重写了 forward，不复用父类的"一条道走到黑"（父类只输出最终特征），而是每个 stage 拆开取中间产物：

输入 x: (B,3,H,W)
│
├─ patch_embed（v2版：两层3x3卷积各stride=2）
│     (B,3,H,W) → (B,128,H/4,W/4)        # 一次性把分辨率降到 1/4
│
├─ i=0: x = layers[0].blocks(x)          # VSSBlock×2 @ 1/4,  128ch
│        y = layers[0].downsample(x)     # → 下一级输入 (B,256,H/8,W/8)
│        outs.append(outnorm0(x))        # ★ 收集的是 blocks 输出，不是 downsample 后的
│
├─ i=1: blocks @ 1/8, 256ch → downsample → (B,512,H/16,W/16)
│        outs.append(outnorm1(x))
│
├─ i=2: blocks @ 1/16, 512ch → downsample → (B,1024,H/32,W/32)
│        outs.append(outnorm2(x))
│
└─ i=3: blocks @ 1/32, 1024ch
         downsample = nn.Identity（末级占位，白跑一次）
         outs.append(outnorm3(x))

返回 outs = [(B,128,H/4), (B,256,H/8), (B,512,H/16), (B,1024,H/32)]

layer_forward 里的返回值分工（Mamba_backbone.py:70-73）值得注意：x 是 blocks 输出（被收集），y 是 downsample 输出（继续传）——取的是下采样之前的特征。

最后一个兜底分支（if not self.channel_first: out.permute(0,3,1,2)）保证无论配置成 ln（channel-last）还是 ln2d/bn，输出永远是 (B,C,H,W)——这就是下游解码器不用操心布局的原因。

3decoder_T1 = SemanticDecoder（独立解析，decoder_T2 同构）

定位：单一时相的语义分割解码器。T1、T2 两个实例结构逐层相同、参数完全独立，各自只看自己时相的编码特征。

3.1 构造时的零件清单（SemanticDecoder.py:33-99）

组件数量配置
VSSBlock4 个st_block_4/3/2/1_semantic，通道 1024/512/256/128，drop_path=0.1
PyramidFusion3 个down_sample_1/2/3：1024→512、512→256、256→128
ResBlock4 个smooth_layer_3/2/1_semantic（三级等宽）+ smooth_layer_0_semantic(128)（末级额外平滑）

每个 VSSBlock 同样被 Permute/Identity 包裹（channel_first=True 时为恒等）。与 ChangeDecoder 的构造差异有两点：没有 FFT_Fusion（单时相不需要双时相融合），多出一个 smooth_layer_0_semantic（最细级输出前的最后一段 128 通道平滑，对齐分类头的输入通道）。

3.2 forward 入口拆包

feat_1, feat_2, feat_3, feat_4 = features      # 本时相 4 级特征，细→粗 128/256/512/1024
change_map_1, change_map_2, change_map_3, change_map_4 = change_maps   # 尺度一一对应

3.3 Stage I（1/32，1024 通道）—— 三步

四级共用同一条流水线，以最粗级为例：

p4 = feat_4                                     # 起点：原始编码特征 (B,1024,H/32,W/32)
        │
        ▼ ① CGA 变化引导（本级灵魂步骤）
p4 = ChangeGuidedAttention()(feat_4, change_map_4)
        # 无参数纯函数：attention = sigmoid(change_map_4)
        # 输出 = feat_4 × attention —— 变化区保留、非变化区抑制
        # 注意 change_map 与 feat_4 同为 1024 通道，故能逐元素直接乘
        │
        ▼ ② Mamba 时空建模
p4 = st_block_4_semantic(p4)
        # VSSBlock: x + DropPath(SS2D(norm(x))) + DropPath(MLP(norm2(x)))
        │
        ▼ ③ 通道降维（不改分辨率）
p4 = down_sample_1(p4)      # PyramidFusion 1024→512，(B,512,H/32,W/32)

3.4 Stage II（1/16，512 通道）—— 完整五步

从这级起出现完整的"先验注入"步骤，顺序与 ChangeDecoder 略不同——CGA 放在最前面：

p3 = ChangeGuidedAttention()(feat_3, change_map_3)    # ① 先用变化图条件化
p3 = _upsample_add(p4, p3)                            # ② 再注入粗先验
        # p4 已是512ch → interpolate 到 H/16 → 与(被CGA处理过的)p3 相加
p3 = smooth_layer_3_semantic(p3)                      # ③ ResBlock+SE 平滑
p3 = st_block_3_semantic(p3)                          # ④ VSSBlock(512)
p3 = down_sample_2(p3)                                # ⑤ 512→256
ℹ 与 ChangeDecoder 不一样的细节 _upsample_add 加的是被 CGA 条件化过的 p3，不是 feat_3 原始特征——变化引导的影响会顺着相加传播到后面每一级。

Stage III / IV 逐级复制同一模式：256ch → 128ch。最细级略有不同：

p1 = ChangeGuidedAttention()(feat_1, change_map_1)   # CGA @ 1/4, 128ch
p1 = _upsample_add(p2, p1)                           # 注入先验
p1 = smooth_layer_1_semantic(p1)                     # ResBlock(128)
p1 = st_block_1_semantic(p1)                         # VSSBlock(128)
p1 = smooth_layer_0_semantic(p1)                     # ★ 多出的第五步：128ch 再平滑一次
return p1                                            # (B,128,H/4,W/4)

_upsample_add 与 ChangeDecoder 中是同一个双线性放大+相加实现（各文件里各有一份拷贝，代码重复）。

3.5 三点独立说明

  • CHANGE_GUIDED_ATTENTION 是写死的 True 开关（SemanticDecoder.py:37），关掉就退化成普通语义分割解码器；
  • 每级 ChangeGuidedAttention() 都是临时 new 的实例——它无参数无状态，等价于直接调 feat * sigmoid(map) 函数；
  • for_figs 列表收集 CGA 后特征，是画图用的遗留代码，训练路径不消费它。

4分类头 main_clf_cd / aux_clf = PyramidFusion（独立解析）

定位：两个是同一个类、同一种用法的分类头，仅输出类别数不同。aux_clf 一份权重被 T1/T2 两次 forward 调用共用（权重共享是有意设计——两期地物分类体系相同）；main_clf_cd 只被 BCD 分支调用一次。

4.1 内部逐层调用（GuidedFusion.py:108-128）

与解码器里做"下采样融合"时是同一个模块，这里当分类头用时通道配置换成 in=128, out=2 或 C：

输入 x: (B,128,H/4,W/4)
│
├─ shortcut = Conv2d(128→out, 1x1)        # in≠out，残差捷径用 1x1 对齐通道
│
├─ b1 = Conv1x1(128→out)+BN+ReLU           # 分支1：逐像素
├─ b3 = Conv3x3(128→out)+BN+ReLU           # 分支2：3x3 小感受野
├─ b5 = DWConv5x5(128→128) → Conv1x1(→out)+BN+ReLU   # 分支3：5x5 深度可分离，大感受野
│
├─ cat[b1,b3,b5] → (B, 3·out, H/4, W/4)
│
├─ channel_att = ChannelAttention(3·out)
│     # GAP+GMP → 共享两层FC(3·out → 3·out/16 → 3·out) → sigmoid → (B,3·out,1,1)
│     weighted = cat × channel_weights
│
├─ spatial_att = SpatialAttention()
│     # 通道维 mean+max → (B,2,h,w) → 7x7卷积 → sigmoid → (B,1,h,w)
│     weighted = weighted × spatial_weights
│
├─ final_conv = Conv1x1(3·out→out)+BN+ReLU
│
└─ return final_conv(weighted) + shortcut(x)    # 残差相加
输出: (B, out, H/4, W/4)

4.2 当分类头用时的三个独立性质

  1. 不做任何分辨率变换：PyramidFusion 的所有卷积都是 stride=1、padding 对齐，输出空间尺寸恒等于输入。所以两个头吐出的是 1/4 分辨率的 logits（(B,2,H/4,W/4) / (B,C,H/4,W/4)），放大回原图尺寸的动作发生在这层之外（STMambaSCD.forward 里的 F.interpolate），不属于头本身。
  2. CBAM 序列是"先通道后空间"，且空间注意力作用在已被通道加权后的特征上（串联加权，非并行）。
  3. shortcut 分支包含可学习参数：in≠out 时是 1×1 卷积而非恒等，意味着残差捷径本身也在参与"128 通道 → 类别 logits"的映射，与主分支输出直接相加。对 main_clf_cd 而言 shortcut 是 Conv1x1(128→2)——一个直接从特征线性投到 2 类的旁路。

三层各自的职责：encoder 负责"把一张图变成四级金字塔特征"，SemanticDecoder 负责"在变化图约束下把单时相特征精修成 128 维语义特征"，分类头负责"把 128 维特征线性加权成类别得分"。

5值得注意的点（遗留代码与实现细节）

  1. 调用链的"暗线"：BCD 分支的产出 change_maps 是 SCD 分支的引导输入，STMambaSCD.py:149 的 change_maps[::-1] 反转是衔接关键——ChangeDecoder 按粗→细产出，SemanticDecoder 按细→粗消费。
  2. 遗留/未使用代码不少：MultiScaleChangeGuidedAttention 和 MultiScaleChangeGuidedAttention_StageByStage 两个变体无任何模型引用；FFT_Fusion 里的 CrossAttention 定义了但 forward 没调用；DepthwiseSeparableConv 只被导入未使用；各文件顶部大量重复 import（os/time/fvcore 等）是沿用 VMamba 原仓库的遗留。
  3. CGA 每级都 new 一个实例（SemanticDecoder.py:124 等）：因为无参数，功能上等价于直接调函数，不影响正确性。
  4. 配套文档：同目录下还有 ARCHITECTURE.md，可对照阅读更细的逐模块说明。
