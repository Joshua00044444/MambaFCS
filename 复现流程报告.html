🚀 Mamba-FCS 完整复现流程报告

Mamba-FCS: Joint Spatio-Frequency Feature Fusion, Change-Guided Attention, and SeK Loss for Enhanced Semantic Change Detection in Remote Sensing

IEEE JSTARS 2026（DOI: 10.1109/JSTARS.2026.3663066）· arXiv: 2508.08232 · 官方仓库：github.com/Buddhi19/MambaFCS

任务：遥感语义变化检测（SCD） 数据集：SECOND / Landsat-SCD 骨干：VMamba-Base 本报告基于仓库 D:\MambaFCS 当前源码逐文件核对生成

项目速览

Mamba-FCS 输入同一区域双时相影像 T1（前期）/ T2（后期），同时输出三张图：

  • 二元变化图 output_bcd (B,2,H,W) —— 哪里发生了变化；
  • T1 语义分类图 output_T1 (B,C,H,W) —— 前期地物类别；
  • T2 语义分类图 output_T2 (B,C,H,W) —— 后期地物类别。

三大核心创新（也是消融实验的对象）

创新点代码位置作用
JSF 空频融合（FFT_Fusion）changedetection/models/GuidedFusion.py把 FFT 对数幅度谱注入空间特征，对光照/季节变化更稳健、边界更锐利
CGA 变化引导注意力changedetection/models/SemanticDecoder.py + MultiScaleChangeGuidedAttention.py特征 × sigmoid(变化图)：变化区域增强、非变化区域抑制，引导两期语义解码
SeK 损失changedetection/utils_func/loss.py → SeK_Loss在变化区域内直接优化 soft-Kappa + 频率加权 mIoU，缓解长尾类不平衡

底层骨干为 VMamba（vssm_base_0229，4 级输出 128/256/512/1024 通道），依赖自编译的 selective_scan CUDA 内核。

4编译 Selective Scan CUDA 内核（关键步骤）

VMamba 的 SS2D 扫描依赖 kernels/selective_scan 中的自定义 CUDA 算子（SelectiveScanOflex 等），不编译则模型无法前向。

4.1 通用构建流程（必读）

cd kernels/selective_scan
pip install . --no-build-isolation     # ★ 必须加 --no-build-isolation
cd ../..
⛔ 为什么必须 --no-build-isolation 该目录只有 setup.py、没有 pyproject.toml，setup.py 在构建期 import torch。pip 默认的构建隔离会新建一个没有 torch 的临时环境，导致 ModuleNotFoundError: No module named 'torch'。

4.2 按 GPU 架构修改 setup.py（首次编译前）

当前 setup.py 内置的 gencode 为 sm_80 + sm_86（并按条件附加 sm_90），与官方机器 RTX A5000 匹配。其他显卡必须编辑 kernels/selective_scan/setup.py 中的 -gencode 行：

你的 GPU架构gencode 写法
A100 / A800sm_80arch=compute_80,code=sm_80
RTX 3090 / A5000 / A6000sm_86arch=compute_86,code=sm_86（默认已含）
RTX 4090 / 4080 / L40sm_89需把 86 那行改为 arch=compute_89,code=sm_89（或追加）
H100 / H800sm_90arch=compute_90,code=sm_90

查自己显卡架构：python -c "import torch; print(torch.cuda.get_device_capability(0))"，输出如 (8, 9) → sm_89。

4.3 CUDA 13（cu130）构建且系统无对应 toolkit 时（无 root 也可行）

若 torch 是 cu130 构建、系统只有 CUDA 12.x 或没有 toolkit，把匹配的编译器装进虚拟环境即可（torch 已自带 cu13 运行时/头文件）：

cd kernels/selective_scan
# CUDA 13 编译器 + CCCL(CUB/Thrust) 头文件 + ninja
pip install "cuda-toolkit[nvcc,cccl]==13.0.2" ninja
# 把 nvvm/crt 钉在与 nvcc 相同的版本(13.0.88)，否则新版前端产出的 PTX
# 会被 13.0 的 ptxas 拒绝："Unsupported .version 9.3"
pip install "nvidia-nvvm==13.0.88" "nvidia-cuda-crt==13.0.88"

# 运行库只有 libcudart.so.13，链接器需要不带版本号的软链
CU=$(python -c "import os,nvidia;print(os.path.join(os.path.dirname(nvidia.__file__),'cu13'))")
ln -sf libcudart.so.13 "$CU/lib/libcudart.so"

# 指向虚拟环境内的 CUDA 工具链并构建
export CUDA_HOME="$CU"; export PATH="$CU/bin:$PATH"
export LD_LIBRARY_PATH="$CU/lib:$LD_LIBRARY_PATH"
export MAX_JOBS=4                     # 限制并行 nvcc 数，防内存爆
pip install . --no-build-isolation
cd ../..

CUDA 13 需要的两处源码修改（去掉 Volta gencode、给 CUB 3.0 加 LaneId/CTA_SYNC shim）仓库中已经改好，换上游新 checkout 才需重做，详见 kernels/selective_scan/README.md。

6.3 标签转换脚本（RGB 彩色标签 → 整数类别图）

若拿到的 SECOND 标签是彩色图，用官方 notebook 中同款颜色表做反向映射：

import numpy as np, imageio, os
from pathlib import Path

color2id = {
    (255,255,255):0, (0,128,0):1, (128,128,128):2,
    (0,255,0):3,     (0,0,255):4, (128,0,0):5,   (255,0,0):6,
}

def convert_folder(src_dir, dst_dir):
    Path(dst_dir).mkdir(parents=True, exist_ok=True)
    for name in os.listdir(src_dir):
        rgb = imageio.imread(os.path.join(src_dir, name))[:, :, :3]
        out = np.zeros(rgb.shape[:2], np.uint8)
        for c, i in color2id.items():
            out[np.all(rgb == np.array(c, np.uint8), axis=-1)] = i
        imageio.imwrite(os.path.join(dst_dir, name), out)

# 示例：convert_folder('SECOND_raw/train/label1', 'SECOND/train/GT_T1')

7配置文件详解

训练由 YAML 驱动：configs/train_SECOND.yaml 与 configs/train_LANDSAT.yaml。字段含义（与 train.py:_build_args 逐一对应）：

字段必填含义与注意
cfg✓骨干结构配置，固定 MambaFCS/changedetection/configs/vssm1/vssm_base_224.yaml（EMBED_DIM=128, DEPTHS=[2,2,15,2], forward_type=v3noz 等），按"仓库上一层目录"解析
pretrained_weight_path✓VMamba 预训练权重路径（第 5 节），建议绝对路径
dataset✓SECOND 或 LandSat（决定数据类与 SeK 预热策略，区分大小写）
dataset_root数据根目录；列表文件相对它解析
train_dataset_path / test_dataset_path✓训练/测试集目录（相对 dataset_root 解析）
train_data_list_paths / test_data_list_path✓列表文件（可为多个，Landsat 训练即 train+val 两个）
batch_size / crop_size / max_iters见 6.4 表；max_iters 是 DataLoader 迭代步数（数据会循环采样补齐）
learning_rate / weight_decay默认 1e-4 / 5e-4（AdamW）
num_classes语义类别数：SECOND=7、LandSat=5
model_type / model_param_path / model_saving_name✓模型类型固定 MambaSCD_base；checkpoint 存到 model_param_path/model_saving_name/
cuda / cuda_device单卡训练；cuda_device 指定卡号（等价 CUDA_VISIBLE_DEVICES 单卡化）
resume / optim_path / scheduler_path断点续训：三者必须同时提供（模型 / 优化器 / 调度器状态）
do_validationtrue 时训练结束后再跑一次完整验证

所有字符串字段支持 $ENV/${ENV} 环境变量展开，也可配合仓库根 .env 文件（train.py 会自动尝试加载）。

最优 checkpoint<model_param_path>/<model_saving_name>/<iter>_model_<SeK>.pth
如 ~/MambaFCS_saved_models/JOURNAL1/SECOND_FULL/20000_model_0.253.pth
TensorBoard 日志<仓库上一层目录>/saved_models/<model_saving_name>/logs/

⚠ 路径解析规则（train.py 源码行为） cfg / pretrained_weight_path / model_param_path / resume / optim_path / scheduler_path 按"仓库上一层目录"解析相对路径；数据集与列表路径按 dataset_root 解析。因此 YAML 中的相对路径会落到仓库外面（与 README 的 saved_models 描述不同）——建议全部写绝对路径，一劳永逸。

8.4 训练内部行为（便于判断是否正常）

  • 优化器：AdamW（lr=1e-4，wd=5e-4）；调度器：StepLR 每 10000 步 lr 减半。
  • 损失 = 1.0×CE(BCD) + 0.5×[CE(T1)+CE(T2)] + 0.5×[Lovász(BCD/T1/T2)] + 0.05×时序一致性MSE + 0.5×SeK；语义损失只在变化区域内监督（非变化像素置 255 忽略）。SECOND 从第 0 步启用 SeK，LandSat 从 150000 步后启用。
  • 验证频率：每 5000 步验证一次（>30000 步后加密为每 1000 步）；验证集 batch=1，输出 Kappa / FSCD / mIoU / SeK / OA，按 SeK 最优保存权重并写入 TensorBoard。
  • 每 10 步打印一次各路损失；训练全程吃满单卡约 20+ GB 显存（bs=2, crop=512）。
  • 断点续训：YAML 同时填 resume（模型权重）、optim_path（optimizer.state_dict）、scheduler_path（scheduler.state_dict），并把 start_iter 设为对应步数。
  • 尽早拿到可用模型：官方发布的 SECOND 最优出现在 2 万步、Landsat 在 10.5 万步左右，远小于 max_iters —— 复现时可先跑到出现最优 checkpoint 后用其做评估，再决定是否跑满。

8.5 训练时长参考

以 RTX A5000（24 GB）为基准：SECOND（bs=2, crop=512）约 3～4 it/s 量级，80 万 iters 需 3～5 天；Landsat 更长。建议多消融实验用不同 cuda_device 并行（每个消融约占一张卡）。

13常见问题与踩坑清单（源码核对汇总）

  1. 内核编译 No module named 'torch' —— 忘加 --no-build-isolation（第 4.1 节）。
  2. nvcc 与 torch CUDA 大版本不一致导致构建中止 —— 对照 torch.version.cuda 与 nvcc --version；无 root 用 4.3 节虚拟环境内 toolkit 方案。
  3. 显卡架构不匹配（如 RTX 4090=sm_89，默认 gencode 只有 80/86）—— 编译前改 setup.py 的 -gencode（第 4.2 节）。
  4. pip install -r requirements.txt 失败 —— 清单里的 cv2 包名不存在，替换为 opencv-python；并补装 einops tqdm pyyaml python-dotenv thop。
  5. ModuleNotFoundError: No module named 'MambaFCS' —— 克隆目录没叫 MambaFCS，或不在该目录内启动训练（第 3.2 节硬约束）。
  6. SECOND 数据找不到文件 —— README 写的 A/B/labelA/labelB 与 SECOND 数据类实际读取的 T1/T2/GT_T1/GT_T2/GT_CD 不一致，按第 6.1 节布局组织。
  7. 标签类别错乱 / 指标异常偏低 —— 标签用了 RGB 彩色图；必须转成单通道整数类别图，GT_CD 为 0/255 二值（第 6.3 节脚本）。
  8. checkpoint / TensorBoard 落盘位置与 README 不符 —— 相对路径按"仓库上一层目录"解析（第 8.3 节）；建议 YAML 全用绝对路径。
  9. resume 报错缺 optim/scheduler —— 续训必须同时给 resume + optim_path + scheduler_path。
  10. batch_size 差异 —— README 声明"全部实验 batchsize=2"，但随仓库的 train_LANDSAT.yaml 为 batch_size: 10, crop_size: 416。忠实复现论文建议以 README（bs=2）为准做敏感性对照，或按 YAML 现值复现作者实际产物（Landsat 官方 checkpoint 由该配置训出）。
  11. 显存不足 OOM —— bs=2×crop512 约 20+ GB；不足时可减 batch 并等比降 lr，或换 crop 416。多卡并行时每张卡跑一个独立进程（改 cuda_device），代码本身是单卡训练，无 DDP。
  12. import 内核报 libcudart.so.13: cannot open shared object file —— 按第 4.4 节补 LD_LIBRARY_PATH。
  13. 训练很慢 —— 确认 nvidia-smi 中进程在 GPU 上、数据在本地盘（NFS 挂载会拖垮 num_workers=16 的读取）；首次验证（5000 步）之前只有日志滚动属正常。
